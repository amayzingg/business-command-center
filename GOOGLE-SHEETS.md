# Connect a Google Sheet (private)

> **Status: tested** (November 2026). The Google Cloud console changes often, so menu names
> may differ. The code is generated by your AI tool from the prompt below, so check the
> result in the browser.

Good fits: data you maintain by hand, such as **leads, tasks, goals, habits, content
calendar, simple KPIs**. For data that already lives in a tool (Stripe, Notion…), connect
that tool instead.

## Why a service account (not an API key)
A plain Google API key can only read a sheet that's shared as **"Anyone with the link"**,
which makes your business data public. A **service account** is a robot Google user. You
share the sheet with just that robot (as Viewer), so the sheet stays private. The
dashboard reads it server-side (a Cloudflare Pages Function), so the key never reaches
the browser.

## 1. Lay out the sheet
- **One tab per dataset**, e.g. `Leads`, `Tasks`, `Goals`.
- **Row 1 = headers**, one record per row below, plain values (no merged cells, no
  totals rows, no formatting-only rows). Formulas are fine, because the API returns their values.
- Match the dashboard's field names where you can, so widgets work unchanged. For
  example, `Tasks`: `id | title | due | priority | done` with `due` as `2026-11-14` and
  `done` as `TRUE`/`FALSE`.
- Copy the **sheet ID** from its URL: `docs.google.com/spreadsheets/d/<SHEET_ID>/edit`.

## 2. Create the service account (Google Cloud console, ~10 min)
1. Go to https://console.cloud.google.com → project picker → **New project** (e.g.
   `command-center`). No billing needed for the Sheets API at this volume.
2. **APIs & Services → Library** → search **Google Sheets API** → **Enable**.
3. **IAM & Admin → Service accounts → Create service account**. Name it e.g.
   `dashboard-reader`. **Skip the roles step** (it needs no project roles) → Done.
4. Open the new service account → **Keys** tab → **Add key → Create new key → JSON** →
   Create. A `.json` file downloads, and you can't download it again.
   **"Key creation is disabled"?** See [If key creation is blocked](#if-key-creation-is-blocked-google-workspace) below.
5. Copy the service account's **email** (`dashboard-reader@<project>.iam.gserviceaccount.com`).

### If key creation is blocked (Google Workspace)
Google Workspace organisations created on or after 3 May 2024 block service account keys by
default, through a policy called **"Disable service account key creation"**. It's a double
negative: **Active blocks keys, Inactive allows them.** These steps make an exception for
one project. Google recommends keeping the organisation-wide restriction and creating
exceptions only for projects that need keys, so don't turn it off for the whole organisation.

You need to be a Workspace/Cloud admin. **Alternative:** create the Cloud project with a
personal Google account, which isn't affected. Whether either is OK is your organisation's call.

1. **Give your admin login the role.** Open Google Cloud **IAM**. Use the resource selector
   beside the Google Cloud logo and select your **organisation/domain**. Find your own email
   and click the pencil icon (if it isn't listed, use **Grant access** and enter your email).
   **Add another role** → search **Organization Policy Administrator** → **Save**, keeping
   your existing roles.
   - Assign it to your admin login, **not** the service account.
   - Search by that readable name (the technical ID is `roles/orgpolicy.policyAdmin`). It's
     different from *Organization Administrator*.
   - It must be granted at organisation level, and won't appear in a project's role list.
2. **Select the project** that contains the service account, and confirm its name shows at
   the top. (You grant the role with the organisation selected; you allow key creation
   with the project selected.)
3. **Turn off the restriction for this project.** ☰ → **IAM & Admin → Organization
   Policies** → filter for `iam.disableServiceAccountKeyCreation`. There may be two policies:
   `iam.disableServiceAccountKeyCreation` (original) and
   `iam.managed.disableServiceAccountKeyCreation` (newer). Either one can block key creation.
   - Open the first → **Manage policy** or **Edit policy**.
   - Policy source: **Override parent's policy**.
   - Enforcement: **Off**. If there's a **Rules** section, edit or add a rule with
     enforcement off.
   - **Set policy** or **Save**.
   - If the second policy is Active, repeat for it.
4. **Confirm and wait.** With the project selected, both should show **Inactive**. Allow up
   to 15 minutes, then refresh the service account page.
5. **Create the key.** **IAM & Admin → Service Accounts** → your service account → **Keys →
   Add key → Create new key → JSON → Create**. Save it outside the repo, and don't paste
   the private key into chat.

**If it doesn't work:**
- **Role missing from the picker:** select the organisation before assigning the role.
- **Manage policy is greyed out:** check your login has Organization Policy Administrator.
- **Same error after 15 minutes:** check the policy on the exact project containing the
  service account, not only at organisation level.
- **One policy still Active:** open that row and inspect its enforcement setting.

## 3. Share the sheet with the robot
In the sheet → **Share** → paste the service account email → **Viewer** → untick
"Notify people" → Share. If your Workspace blocks sharing outside the organisation, an
admin has to allow it for this sheet (or use a sheet owned by a personal account).

## 4. Keys: one place, never in the code
From the downloaded JSON, copy two fields into the root **`.dev.vars`** (git-ignored),
plus the sheet ID:
```
GOOGLE_SA_EMAIL=dashboard-reader@your-project.iam.gserviceaccount.com
GOOGLE_SA_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\nMIIE...\n-----END PRIVATE KEY-----\n"
GOOGLE_SHEET_ID=1AbCdEf...
```
- Keep the private key on **one line**, in double quotes, with the `\n`s exactly as they
  appear in the JSON.
- Then **delete the downloaded `.json` file** (or move it outside the project folder).
  Never put it in `src/`, `public/` or anywhere in the repo.
- `npm run secrets:push` uploads these to Cloudflare for the dashboard (and the weekly
  email), like your other keys. Then redeploy.

## 5. Have your AI tool build it
Paste this into Claude Code or Codex (change the tab names and fields to yours):

> Add a private Google Sheets source, following GOOGLE-SHEETS.md and CLAUDE.md:
> 1. `shared/sheets.js`: get an OAuth access token for a service account
>    (`GOOGLE_SA_EMAIL`, `GOOGLE_SA_PRIVATE_KEY`, scope
>    `https://www.googleapis.com/auth/spreadsheets.readonly`) by signing an RS256 JWT
>    with **WebCrypto** (`crypto.subtle.importKey` with PKCS#8 and
>    `RSASSA-PKCS1-v1_5`/SHA-256). **Don't use the `googleapis` npm library:
>    Cloudflare Workers can't run it.** Exchange the JWT at
>    `https://oauth2.googleapis.com/token`. Turn literal `\n` in the private key into
>    newlines first. Then read tabs with `GET
>    https://sheets.googleapis.com/v4/spreadsheets/{GOOGLE_SHEET_ID}/values/{Tab}` and
>    turn rows into objects using the header row. Convert `TRUE/FALSE` to booleans and
>    numeric columns to numbers.
> 2. `functions/api/sheets.js`: return `{ tasks: [...], leads: [...], live: { sheets:
>    { fetchedAt } } }` in the same shapes as `src/data/sample.json`, with
>    `Cache-Control: no-store`. Return 501 with a clear message if a key is missing.
> 3. Add `/api/sheets` to `SOURCES` in `src/liveData.js`.
> 4. If `email-worker/` exists, load the same data in `email-worker/src/index.js` the
>    way Stripe is loaded.
> 5. Run `npm run build`, test with `npm run dev:functions`, and show me the result.

## 6. Check it
- `npm run dev:functions` → http://localhost:8788. The header should show **Live: sheets**,
  and your widgets should show the sheet's rows. Edit a cell, click **Refresh**, and it updates.
- `npm run secrets:push`, build + deploy. The `/api/sheets` route is behind your Access login.

## Troubleshooting
- **403 / "The caller does not have permission":** the sheet isn't shared with the
  service account email, or the Sheets API isn't enabled in that project.
- **"invalid_grant" / JWT errors:** the private key lost its `\n`s or quotes, or the
  computer's clock is off.
- **Widgets show nothing:** the column names don't match the fields the widget reads.
  Rename the headers, or ask your agent to map them.
