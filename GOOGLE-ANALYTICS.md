# Connect Google Search Console and GA4

> **Status: untested end to end.** The steps follow Google's docs as of November 2026 (the
> console UI changes often). The code is generated by your AI tool from the prompt below, so
> check the result in the browser.

Adds two live sources to your dashboard: **search performance** (clicks, impressions, CTR,
average position, top queries and pages) and **site traffic** (users, sessions, top pages).

**Before you start:** you need the service account from [`GOOGLE-SHEETS.md`](GOOGLE-SHEETS.md)
(steps 2 and 4). The same `GOOGLE_SA_EMAIL` and `GOOGLE_SA_PRIVATE_KEY` are reused here, so
there's no new key to create. You don't need a Google Sheet connected.

## 1. Enable the APIs
In the same Google Cloud project: **APIs & Services → Library**. Search for and **Enable**:
- **Google Search Console API**
- **Google Analytics Data API**

## 2. Give the service account access
Use the service account's email (`dashboard-reader@<project>.iam.gserviceaccount.com`).
You need to be an owner or full user of the Search Console property, and an administrator
of the GA4 property.

- **Search Console:** open your property → **Settings → Users and permissions → Add user** →
  paste the email → permission **Restricted**.
- **GA4:** **Admin** → under Property, **Access management** → **+ → Add users** → paste the
  email → untick "Notify new users by email" → role **Viewer** → **Add**.

## 3. Add the settings to `.dev.vars`
In the root `.dev.vars` (git-ignored), alongside your other keys:
```
GSC_SITE_URL=sc-domain:yourdomain.com
GA4_PROPERTY_ID=123456789
```
- **`GSC_SITE_URL`** must match the property exactly. Domain property:
  `sc-domain:yourdomain.com`. URL-prefix property: the full URL with its trailing slash, e.g.
  `https://www.yourdomain.com/`.
- **`GA4_PROPERTY_ID`** is the number under **Admin → Property settings**. It's not the
  `G-XXXXXXX` measurement ID.

## 4. Have your AI tool build it
Paste this into Claude Code or Codex:

> Add Google Search Console and GA4 as live sources, following GOOGLE-ANALYTICS.md and
> CLAUDE.md. Reuse the service account login from the Google Sheets source if the project has
> one (`shared/sheets.js`). If not, create `shared/google-auth.js`: get an OAuth access token
> for `GOOGLE_SA_EMAIL` / `GOOGLE_SA_PRIVATE_KEY` by signing an RS256 JWT with **WebCrypto**
> (`crypto.subtle.importKey` with PKCS#8 and `RSASSA-PKCS1-v1_5`/SHA-256), exchanging it at
> `https://oauth2.googleapis.com/token`, and turning literal `\n` in the key into newlines
> first. **Don't use the `googleapis` npm library: Cloudflare can't run it.**
> 1. Add `functions/api/google-search.js` using scope
>    `https://www.googleapis.com/auth/webmasters.readonly`. POST to
>    `https://www.googleapis.com/webmasters/v3/sites/{URL-encoded GSC_SITE_URL}/searchAnalytics/query`
>    with `startDate`, `endDate` (YYYY-MM-DD) and `dimensions`. Return clicks, impressions, CTR
>    and average position for the last 28 days, plus top queries and top pages (`query` and
>    `page` dimensions, `rowLimit` 10). End the range 3 days ago because recent data lags.
> 2. Add `functions/api/analytics.js` using scope
>    `https://www.googleapis.com/auth/analytics.readonly`. POST to
>    `https://analyticsdata.googleapis.com/v1beta/properties/{GA4_PROPERTY_ID}:runReport`
>    with `dateRanges` (`28daysAgo` to `today`), `metrics` (`totalUsers`, `sessions`) and, for
>    top pages, `dimensions` (`pagePath`) with `screenPageViews`.
> 3. Each route returns a partial `data` object in the shape `src/liveData.js` merges:
>    `{ search: {...}, live: { search: { fetchedAt } } }` and
>    `{ traffic: {...}, live: { analytics: { fetchedAt } } }`, where `fetchedAt` is when Google
>    was actually called. Cache each response on the server for one hour (KV with
>    `expirationTtl: 3600` if a KV binding exists, otherwise the Cache API). Return 501 with a
>    clear message if a value is missing. Add both routes to `SOURCES` in `src/liveData.js`.
> 4. Add `SearchPerformance` and `SiteTraffic` widgets that read `data.search` and
>    `data.traffic`, and show an empty state when they're missing. Run `npm run build`, test
>    with `npm run dev:functions`, and show me the result.

## 5. Ship
```bash
npm run secrets:push
```
```bash
npm run deploy
```
`secrets:push` uploads everything in the root `.dev.vars`, including these two settings.

## What to expect
- **Search Console usually lags 2–3 days**, so the newest days are missing.
- **GA4 standard reports can take hours to fill in**, and the last day or two can still
  change. GA4's real-time report is separate and isn't used here.
- **The one-hour cache matters.** The dashboard refetches every 5 minutes while it's open,
  and GA4 has usage limits. "Live" here means up to an hour old on top of Google's own delay.

## Troubleshooting
- **403:** the service account wasn't added to that property (step 2), or that API isn't
  enabled in the same Cloud project (step 1).
- **Empty Search Console results:** `GSC_SITE_URL` often doesn't exactly match the property.
  Check `sc-domain:` versus a full URL, `https` versus `http`, `www`, and the trailing slash.
- **GA4 400 or 404:** `GA4_PROPERTY_ID` should be the numeric property ID, not `G-XXXXXXX`.
- **Value "is missing" locally:** check the exact names in `.dev.vars`, then restart
  `npm run dev:functions`.
